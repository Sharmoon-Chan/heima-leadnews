## 必做离线验证

在独立测试根目录，用模拟请求/Redis/SQL 回调计数和哨兵文件完成：

| 场景 | 验收 |
|---|---|
| 全新合法 run_id/OutDir | 元数据创建成功，路径对应明确 |
| 已有空目录、已有非空目录 | 都拒绝；外部回调 0 次，原目录内容/哨兵 hash 不变 |
| run_id 与目录不符、非法路径 | 调用前失败，不创建业务运行输出、不访问服务 |
| 模拟中途异常 | 已写响应/错误/元数据保留，状态 failed、非零退出；没有 finally 清理原件 |
| 同一 ID 重试、换新 ID 重试 | 前者拒绝且旧证据不变；后者另建目录可运行，旧目录保留 |
| HTTP 非成功、业务码 503、非法 JSON、缺响应文件 | 各自为失败，原响应/错误可查；不能因 HTTP 200 单独算成功 |
| 前置未完成 | 明确 skipped/not_executed，不能累计为通过的功能断言 |

不为验证留存而重跑所有缓存功能或连接共享服务。若某验证不适用于预热/负载的输出结构，说明统一保护已接入及该入口的结果结构，不虚构它有完整单响应文件。
