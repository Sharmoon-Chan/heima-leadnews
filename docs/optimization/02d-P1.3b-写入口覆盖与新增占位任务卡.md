## 三项最小业务修复

**S：static_url 写入。** 先用真实应用入口复现：预热详情 V0，调用 buildArticleToMinIO，DB 已为新 URL 而详情仍旧。优先在该实际异步写入口 UPDATE 成功后登记同一失效器，由其真实事务提交后删除；若确需按 ID 更新 static_url 的窄服务方法，可最小补接口，不为本卡重构通用写入层。保留外层异步/事务与消息顺序，不用自调用注解假装开启事务，不重写静态化流程。0 行更新不伪报成功失效；处理结果与原业务行为的取舍记录清楚。

允许只在本轮装配中替换 FileStorageService（返回明确标注的实验 URL）和 KafkaTemplate（记录调用、不发消息），但必须运行真实 Freemarker 模板、实际异步方法、DAO、事务和失效器。P1.3a 的整个 Freemarker no-op 替身需关闭；不能再用同句 SQL 模拟冒充入口通过。记录异步实际完成/提交时点，不把调用方立即返回当完成；真实 MinIO、消息发送与 ES 落地仍归 P2.0。

S 回滚必须在真实异步工作线程的事务内发生，例如在 UPDATE/失效登记之后由消息记录替身同步抛 RuntimeException；调用线程的事务不会跨线程传播，不能用调用方 TransactionTemplate 回滚冒充异步 SQL 回滚。关联 worker 的 afterCommit/afterCompletion 和独立 DB 值；void 异步方法返回或任务提交成功不算完成。

正文使用模板可处理的合法数组，例如 `[{"type":"text","value":"P13b-marker"}]`；上传替身读取并记录 HTML 含对应标记。现有模板异常会打印后继续，不能仅凭 URL 更新声称模板成功；本卡不改该异常策略。

**B：行为计数写入。** 通过实际 public updateScore 调用运行 updateArticle 的 DB 更新，并为本次真实成功写入登记提交后失效。保留原计数与热榜行为；不用直接调用 private 方法或手写 SQL 作为主证据。选非 null 初值和明确增量，逐字段核对 DB 和详情；重复事件幂等不属于本卡。

updateScore 还会访问频道/推荐热榜 key。使用隔离 Redis DB，或仅替换这些热榜 key 的实验协作者，保留详情/锁 key 的真实 Redis I/O；保存实际隔离方式，不修改课程热榜或事后用全库清空收尾。

**N：新增与空值占位。** 入口 DTO 的 id 必须为 null。在默认关闭、仅精确测试 ID 生效的实验 ID 生成装配中，预定一个不存在 ID：先详情 1002 并确认空值 key，再经真实 saveArticle 新增文章、配置、正文，提交后空值 key 失效，再读为 200 和精确字符串 ID。生产 ID 生成算法保持不变；不得先在 DTO 填 ID、预插业务行或绕过服务直写后冒充新增。确认 ID 夹具确实参与 MyBatis 的实际生成路径；若需要最小测试装配，留存其开关及范围。

可在实验 SqlSessionFactory 实际使用的 GlobalConfig 中装配 IdentifierGenerator：仅目标 ApArticle 标记返回预定 ID，其他实体/请求委托原生成器。配置/正文也各有自己的主键，不能一概强制为文章 ID。原 harness 的必填 id 更新接口不足以证明新增，应有本轮专用 create 入口或可空 id，并保存实际 DTO/分支事件。

## 小规模读写交错成本观察

目的仅是判断计数写入频繁失效会带来多少详情回源，避免只报告正确性收益。固定单个测试文章、同一 JVM/连接池/配置和固定 trace；每 10 次详情读分别均匀插入 0、1、5 次已提交计数写，每档至少 30 个循环。冻结请求顺序及写入增量；先报告实际运行耗时、成功读写数及实际写入速率，不能把计划比例称为达成的每秒速率。

使用一个顺序写者，写事务真实完成后再排后续读。每档从相同字段初值/预热开始，切档前确认前档第二删完成，避免旧定时任务混入下一档；不在本卡混入原有计数并发读改写风险。

从原始事件/响应统计：已提交写数、即时/延迟删除次数、详情回源次数/每百次读、命中与失败数、提交后读到新计数的比例。说明读写串行/并发关系、500ms 第二删对后续缓存的影响；观察结束等本轮已安排的第二删完成并记录尾段。0 写档也要有相同初始预热条件，不把人为清 key 次数算优化收益。不要给物理 SQL 次数，除非有按请求归属的真实 SQL 原件。

这不是稳态容量实验，不做正式 QPS 提升、选延迟参数或全套负载框架改造。若回源增加，照实保留，供 P1.3c/正式对照取舍。
