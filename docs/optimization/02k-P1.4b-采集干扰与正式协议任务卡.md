## 3. 测量路径合同

### 资源不阻断派发

- CPU/内存/线程/可用堆GC观测移到独立观察者或等价隔离机制；采样周期1秒、实际起止/耗时/迟延/缺口记录。主dispatch/reap循环不能等待采样完成或资源写盘。
- observer独立PID，目标Java PID来自实例manifest，collector PID来自本次采集实例；另组空闲Java及无关后台进程如实记录，不取最近Java、不停其他项目进程。
- 观察者输出只在新根；数据交付有界，缺样/不可用有原因，不静默丢弃、填前值或创建无界队列。采集与观察者CPU同时报告整机归一比例、逻辑核数和核等效，包含全部本次采集相关进程。
- 日志/正文序列化、Append/Flush/fsync成本也单列；搬走资源采样不等于所有阻断消失。留存失败继续传播，持续落盘及真实终止前缀保持，不能改为全量结束后才写。

### 时间来源必须可解释

- 每条请求关联rid/slot，记录实际dispatch、**完整客户端HTTP正文可用标记**、主循环观察、落盘/Flush。dispatch与正文标记使用同一单调时间源及冻结的频率/起点；墙钟只作跨进程事件归属辅助。
- 正文标记在拥有完整bytes的请求执行路径中取得，独立于主循环回收/JSON断言/落盘；不使用主循环观察时间冒充正文完成。异步线程不要直接执行无runspace的PowerShell脚本块，可用可靠的小型.NET辅助。
- 此标记不是服务器耗时或TCP最后一字节。若只能取得回调时刻，明确其定义/调度迟滞并用私有控制验证，不能称严格网络终态。传输异常/timeout单独记录终态；没有完整正文时不能补造body-ready/bytes/hash。
