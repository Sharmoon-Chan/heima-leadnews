状态（2026-11-08）：P1–P3相关阶段已验收，用户持续授权下P4实际复测及[最终独立验收](records/20261108-最终独立验收.md)完成，计划工程范围收口。实际材料为[P4最终复测](records/P4-最终复测.md)、[复跑手册](records/P4-最终复跑手册.md)、[事实/简历候选](records/P4-事实与简历候选.md)、[面试复述](records/P4-面试难题与复述.md)。下方保留原派卡模板，方括号不是虚构实测值，实际事实以新材料为准；用户亲自复跑/复述尚未验证。

## 可直接发送的任务摘要

> 只做 P4：依据 docs/optimization 的阶段交接、代码和原始证据做综合复测与结论收口，不新增优化功能。发现缺证据先登记补测，功能回归失败退回对应阶段。交付最终复跑手册、参数表、结果表、简历候选和真实难题卡。JWT 不纳入本轮。不改写正式简历 PDF，先把候选表述与事实依据交给用户。

## 综合验收

- 干净启动或按 V0+已验收差异重建，从环境配置、造数、运行到汇总脚本完整复跑一次。必须确认文档命令仍可执行。
- 对最终组合配置重跑关键功能与故障场景；如果公共配置/打点变了，重跑对应 A/B 基线。历史单项成绩不能直接相加成整个平台提升。
- 最终至少一组稳定读负载、一次热点失效、一次读写竞态、一次 Kafka 故障恢复/重放、一次静态数据集完整翻页。混合负载可选，但必须说明比例与后台任务干扰。
- 输出每组至少三轮的中位数和范围，保留无效轮次及作废理由。性能退化或收益不稳定也需要结论。
- 所有配置选定值与 run_id 对应；默认值与实验选定值分开，回滚默认行为经过验证。

## 简历候选模板

每条控制在一至两句，优先选择一个最有说服力的收益。最终按实际完成情况压缩，不能把所有术语塞回简历。

**缓存（同接口证据充分时）**

> 为文章详情 API 实现 Cache Aside、空值缓存与热点重建互斥，并将缓存失效安排在事务提交后；在 [明确硬件/测试环境]、[文章规模/正文大小]、[负载条件] 下，相比同接口直查 DB，P95 从 [A]ms 降至 [B]ms，单位请求 DB 回源下降 [C]%。

若保留延迟双删，可加“通过受控并发实验验证更新后可见性，延迟窗口选定为 [X]ms”，但要在答辩材料注明非强一致、进程重启等局限。首页热点缓存和新增详情缓存不要混为同一条优化路径。

**Kafka（可靠性证据充分时）**

> 将静态化后的文章索引同步通过 Kafka 解耦，消费端结合 eventId 成功标记与文章 ID 幂等写入处理重复事件；配置 [X] 次重试和死信重放，在 [N] 条逻辑事件、[故障注入条件] 下完成 [实测终态结果]，积压恢复用时 [T]。

若没有完成 Redis 判重则删掉 marker 表述，改为真实 ES 按 ID 幂等；没有验证 Kafka 审核就只写索引同步。样本全部核对成功只能说“该故障实验样本均可对账”，不能写成生产零丢失。

**连续翻页（排序正确性 + 实验对照）**

> 基于 publishTime 与唯一文章 ID 的排序元组实现 search_after 连续翻页，处理同时间文章的分页边界；在 [命中文档数]、每页 [S] 条、深度 [D] 下，相比实验 from/size 对照，单页端到端 P95 由 [A]ms 变为 [B]ms。

如果只有正确性改善、没有稳定性能收益，就写“在固定 [N] 条数据集验证连续遍历无重无漏”，不填提升比例。原项目本来就是时间范围游标，不能写“将原项目的大 offset 改为 search_after”。保留“相比实验对照”或只描述新实现。

## 每个数字旁的答辩证据

内部素材表保存：完整实验条件、run_id、原始数据、计算过程、波动范围、版本和复跑命令。面试时至少能回答：机器配置、并发和请求率区别、数据规模和热点分布、P95 从哪里采、错误怎么断言、为什么对照公平、瓶颈在哪里、哪些结论不能外推。

简历项目时间不得把 2026-10 的补充优化伪装成原 4–7 月已完成。可以标项目持续优化至今，或单列“2026.10 补充优化与本地压测”，由用户最终选择。

## 面试素材最低交付

真实难题优先从实验中自然产生，不为凑故事制造“线上事故”。建议最终挑 2–3 张已复现且证据完整的卡：缓存事务/锁竞态、Kafka 处理器或死信失败、同时间分页边界。没有发生的只保留为风险分析，不能升级成亲历。

每张卡有 60–90 秒讲述、根因时序、失败尝试、方案取舍、前后验证、剩余局限和三层追问。请用户亲自复跑或复述至少一个关键实验，记录掌握状态；agent 完成代码不等于用户已掌握。

## 完成条件

负责人给出最终验收结论；复跑手册有效；结果可定位原始证据；参数有依据；简历候选每句话均与事实一致；难题卡不冒充生产经历；没有以“数字待填”交付为已完成优化。证据不足时保留“实现已完成/压测待完成”的状态，不为了收尾提前发布量化简历。
