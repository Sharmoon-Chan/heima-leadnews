## 所有执行 agent 都须遵守

1. 先读本入口、现状、统一压测规范和本次卡片。仅执行用户派发的一个阶段/子任务，完成后交接并停止。
2. 仓库当前有未提交改动，包括 JWT 和 schedule 的历史改动。保留它们；不得 reset、clean、覆盖文件、混入本次提交。工作区实况优先于旧记录。
3. “待验证”“目标”“实测”分开标记。500ms、3s、60s、重试 3 次等现有常量不是优化成果；不得填造 QPS、延迟或提升比例。
4. 先证明功能与数据正确，再谈性能。HTTP 200 必须再断言业务码、文章 ID、字段和分页集合。可靠性指标不强行包装成吞吐提升。
5. 不升级整套技术栈，不重构审核系统，不新增 JWT 优化，不用外部审核服务耗时充当 Kafka 优化收益。不扩展 Canal、Outbox、完整延迟任务平台；发现相关缺口记账，只有影响本阶段有效性时提出最小修复。
6. 所有参数都有单位、试验条件和证据路径。性能不提升时保留结果，解释原因或调整结论。
