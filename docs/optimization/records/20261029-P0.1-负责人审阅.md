## 3. 接受显式容器工厂，纠正版本措辞

实现调用 Boot 的 configurer.configure(factory, consumerFactory)，然后挂载原处理器，属于本卡可接受的最小接线方式。自定义默认名称的工厂使相应自动配置退让；不是要求开启 Bean 强制覆盖。源码支持沿用 Boot 的配置来源，运行证据确认了 group/topic/分区；不能仅凭 groupId 一项声称所有 ack、并发、序列化细节都逐项验收过。

本地 spring-kafka-2.6.6.jar 的 javap -v 显示 setErrorHandler(ErrorHandler) 没有 Deprecated 标志/注解。故不采用“在 2.6.6 已标记弃用”的说法。将未来升级时的错误处理 API、客户端组合和故障语义回归列为 TECH-001，当前不升级。2.8 引入 CommonErrorHandler 是另一版本的迁移背景，见 [2.8 官方文档](https://docs.spring.io/spring-kafka/docs/2.8.0/reference/html/#annotation-error-handling)。

还需纠正方法级处理器的泛化：KafkaListenerErrorHandler 可以重新抛异常交给容器，不是所有方法级处理器天然只有一次处理；正常返回并吞掉错误才会截断相应失败传播。本轮直接纠正容器级配置的挂载位置，避免无谓改变错误传播。版本契约参考 [2.6.6 官方文档](https://docs.spring.io/spring-kafka/docs/2.6.6/reference/html/#annotation-error-handling)。
