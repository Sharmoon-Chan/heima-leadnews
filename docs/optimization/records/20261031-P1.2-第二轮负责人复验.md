## 尚未通过一：争锁慢失败后追加了预算外 I/O

位置：ApArticleServiceImpl 第 446 行调用 recheckCacheAfterLockFail，第 543 行发 GET，其间未检查 deadline。循环顶部与晚到成功分支已修，但 SET NX 若在预算内发起、耗时超过预算后返回 false，仍会进入此 GET。

负责人用交付的真实 B class 和同一离线替身复现：预算 100ms，SET NX 睡眠 150ms 后返回 false；io.end stage=lock 记录 163ms，随后出现 io.begin stage=recheck。getCalls=2（首读之外又一次）、lockAttempts=1、dbCalls=0、业务码 503。最终失败、没有回源，**不能证明期限后没有新发 I/O**。

只需在慢失败后、重查前补期限检查。最小回归应为 getCalls=1、lockAttempts=1、dbCalls=0、503，且无 io.begin stage=recheck。保留现有 stall/late-acquire 回归。预算内已发起的 GET 晚返回命中是否使用，单独明确策略，不把等待预算扩成整个 HTTP 的硬截止，也不约束正常获锁后的 DB 工作。
