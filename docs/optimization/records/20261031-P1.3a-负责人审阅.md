## A：非目标方法失去事务边界

去掉类级@Transactional影响了整类，不仅getArticleDetail。实际PRE/POST编译类用Spring AnnotationTransactionAttributeSource离线读取结果：

| 方法 | PRE | POST |
|---|---|---|
| saveArticle / updateScore | REQUIRED | REQUIRED |
| getArticleDetail | REQUIRED | NONE（本卡目标） |
| newPage / findNewsComments | REQUIRED | NONE（非目标变化） |

findNewsComments的列表查询和count在服务第888/889行相邻执行；newPage也有分页总数/数据查询。在报告声明的RR条件下，失去原事务会使两次查询可能读不同提交版本。例如列表读到1条后，并发更新把该行移出筛选再提交，count可为0。**这是已确认的事务属性回归及静态并发风险，没有实跑出该脏组合，也不称生产故障。**

本卡只需保留非目标方法原事务语义。简单可行的方案是保留类级事务、仅给getArticleDetail显式NOT_SUPPORTED，再经独立短读事务读取；也可等价显式保留其他方法边界。不要为了修这个问题扩改统计SQL或P1.3b写入口。
