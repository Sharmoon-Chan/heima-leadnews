## 已在报告更正的口径

1. 899 与总量 5399，替代“每组 900”；成功请求分位数原辅助字段漏排序，独立复算更正，执行者 JSON 原件保留。
2. `calcMode=1` 实为 `AllActiveThreads`；固定线程+吞吐计时器不等于严格开环到达。依据本地官方 5.6.3 文档和枚举，单线程组不影响本次目标速率观察。
3. 原吞吐分母是首末请求开始跨度，现同时保留该数并以 count/180s 展示。`costMs` 是 service 方法耗时、`dbSelect` 是 DAO 调用数；撤回纯 MySQL 约 3ms、尖峰因 GC 等无证据推断。
