## 三、过程中发现并如实记录的事实

1. **`content` 必须是 JSON 数组**。首次用纯 HTML 作 `content`，`ArticleFreemarkerServiceImpl` 里 `JSONArray.parseArray(content)` 抛错被 `catch` 吞掉（只 `printStackTrace`），于是上传了一个 **0 字节** 的 html（ETag `d41d8cd9…`），`static_url` 却照写。改成 wemedia 的 `[{"type":"text","value":"…"}]` 后 html 为 8362/8647 字节且含正文。**这是产品现状：静态化失败不会中断流程，也不影响 `static_url` 落库**，建议在 P2.x 或问题台账里跟踪（本卡未改产品代码）。
2. **`content` 字段在本载荷下不可检索**。ES 映射 `content: text + ik_smart`；对 ASCII marker 做 `match` / `match_phrase` / `term` / `query_string` 全部 0 命中，而 `title` 正常。因此“搜索可见”改用**本轮唯一标题**查询，但命中仍必须带目标 `_id` 与本轮 marker（不算“任意命中”）；证据里同时保留 `content_query_total_hits=0` 作为披露。
3. 首版真实路径脚本在 MySQL 处被 `mysql` 的 stderr 密码警告打断（`$ErrorActionPreference='Stop'` + NativeCommandError），当时已发出一篇稿件；已修正并按下述精确收尾清理。
