## 4. 关键结论（都带证据，详见报告）

计数边界：本轮 2/0/1 等来自 dbSelect 的 DAO 调用声明与路径日志，未提供逐请求服务端物理 SQL 的独立轨迹，不扩称全量 SQL 压力证据。

- **正常缓存**：冷读 2 SQL → 热读 0 SQL；TTL 到期后（请求前 `PTTL=-2`）再次 2 SQL 并回填；三次响应逐字节相同（1289 B）。
- **空值缓存**：首次 1 SQL + 写 `__NULL__`（TTL≈8 s）→ 重复请求 0 SQL、业务码仍 1002 → 到期后 1 SQL 并重写。
- **抖动**：12 个 key 的 TTL 落在 19.9–28.9 s（预期 `[20,30)`），7 个不同取值。
- **随机新 ID**：20 个全新 ID 首次全部回源并写占位，第二遍 20 个全部由占位拦住（0 SQL）；
  另 200 个从未请求过的 ID 全部各回源 1 次。本场景 240 次请求共 220 SQL（0.9167 SQL/请求）。
- **补录**：服务写入（`POST /api/v1/article/save`）后 key 立即消失、再查得新内容（**已覆盖**）；
  绕过服务直写 DB 时占位不清、仍返回 1002（**未覆盖**）。
