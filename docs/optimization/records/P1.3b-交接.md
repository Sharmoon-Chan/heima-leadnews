## 5. 口径与边界（读结论前必看）

1. **替身只到出网点**：`FileStorageService` 与 `KafkaTemplate` 是本轮装配的 `@Primary` 替身，明确标注（`p13b-rebuilt://`、记录不发送）。真实 MinIO 上传、真实消息发送、ES 落地仍归 P2.0；不宣称静态化端到端可用。P1.3a 的 Freemarker no-op 替身已关闭，模板真实执行（HTML 含 `P13b-marker` 由替身记录）。
2. **N 的 ID 来自夹具**：`IdentifierGenerator` 只在 `article.p13b.id-fixture.article-id` 精确命中的 `ApArticle` 上返回固定 ID，其他实体/请求委托原生成器；生产算法未改。三表行数断言用 `before+1`，避免把种子既有 config 行当成本次插入。
3. **热榜 key 是与卡面建议的偏差**：没有为 `updateScore` 装热榜协作者替身或隔离 Redis DB，真实写到了 `hot_article_first_page_<channel>` / `hot_article_first_page___all__`。运行结束后 `KEYS 'hot*'` 为空（本地 Redis 中不存在这些 key，课程库未写），但**这不是隔离做法的替代**；下一卡若继续跑 `updateScore` 应先做替身或隔离 DB。已记 TOOL-005。
4. **S 回滚**证明的是「回滚后与回滚前一致 + 登记发生但 afterCommit 与删除都没发生」，该文章在本阶段早先的 S 运行里已有非空 `static_url`，不是「NULL 保持不变」。
5. **脚本断言曾混淆两件事**：REG 原先断言「回滚后缓存未被删」，但同一次 `saveArticle` 还会触发异步 static_url worker（独立事务、合法提交、合法删除）。改为只断言 `saveArticle` 事务自身事件。不是业务缺陷。
6. **P1.3a 既有风险不变**：500 ms 以外的旧读回填、多进程竞态、延迟任务生命周期与参数选择仍留 P1.3c，本卡不重做也不宣称覆盖。
7. 单机、隔离库、单轮小样本；不报 QPS/延迟收益。
