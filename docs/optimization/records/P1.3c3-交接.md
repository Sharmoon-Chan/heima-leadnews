# P1.3c-3 交接：500ms 之外的回填窗口

派卡：2026-11-03。前置：[P1.3c-2 负责人验收](20261103-P1.3c2-负责人验收.md)、[原卡](../02g-P1.3c3-500ms外旧回填与陈旧窗口任务卡.md)。**本卡只测固定 500ms 下的窗口事实**：窗口内控制（W1）与窗口外残留（W2）。业务源码 0 改动；500ms、单线程、`max_active=256`、锁、事务、公开响应均未动。运行细节见[运行时文档](../runtime/P1.3c3-旧回填窗口.md)。

## 1. 结论

- **窗口内（回填早于第二删成功）**：3/3 轮全部按契约收敛。旧回填在第二删**之前**写入，第二删真的把它删掉，之后新发的详情请求读到 **V1**。
- **窗口外（回填晚于第二删成功）**：3/3 轮全部复现残留。第二删已经 `succeeded`，读方才把 V0 写回缓存；此后连续 3 次新发详情请求都读到 **V0**（数据库已是 V1），实测持续 **≥ 1022 / 1035 / 1045 ms**，TTL 观察到 **1800s**（只记下界，不声称等到过期）。
- 即：**固定 500ms 的第二删只能清掉「它之前」的回填**；它之后的回填会留下陈旧值，等 TTL 自然过期才自愈。这不是实现缺陷，是双删策略的边界事实。
- 每轮都只有 1 个慢读者 + 1 个顺序写者；`second_rejected=0`、`first_phase_ok=1`，没有上限拒绝、没有额外 worker 删除，窗口归因不受干扰。
