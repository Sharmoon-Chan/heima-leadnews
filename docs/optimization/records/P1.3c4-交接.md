## 3. 结论（只陈述数据，不选生产参数）

- **200ms 明显更差**：300ms 的回填停顿就已经落在它的第二删之后，命中率 9.67%、回源 271/300，而 500/1500 在同样条件下 0 陈旧、回源 178–198。差异远大于轮间波动（回源 270–271 vs 178–198 互不重叠）。
- **负责人勘误：本组三轮c500成本方向更好，区间不重叠**。命中39.67–40.67% vs34.00–38.33%，回源178–181 vs185–198；同轮c1500多7/7/19次回源。c1500覆盖更多已测慢回填、峰更高，体现取舍；三轮不足以声称普适显著或最优参数。原“区间重叠”表述错误，旧文档快照保留。
- **延迟更大能覆盖更多已测回填，但覆盖不了任意更慢的回填**：300ms→1500ms 的边界移动是真实的（c500 在 300ms 档已覆盖、c1500 在 1500ms 档才覆盖），但 c1500 在 2000ms 停顿档依然 3/3 陈旧。把延迟调大只能右移边界，不能消除窗口外的旧回填。
- 因此**没有共同窗口/成本优势**支持改默认值；本卡不给出"生产最优参数"，保留 500ms 工程默认由负责人决定。

读法：

- **陈旧只出现在「回填之后」**：分支由实际事件顺序判定（`cache.write.done` vs `second_succeeded`），每轮断言「回填早于第二删 → 第二删后所有响应为 V1」「回填晚于第二删 → 回填后所有响应仍为 V0」，27 轮全部自洽。
- **窗口内也确有陈旧**：c500 300ms 档陈旧 9/90（10%）、c1500 300ms 档 46/125（36.8%）。原因是 `V0` 从回填写入到第二删成功之间一直留在缓存里 —— 这段暴露长度近似「第二删延迟 − 回填时刻」：c500 约 0.25s，c1500 约 1.26s。**调大延迟会同时放大这段窗口内暴露**，这是上一轮只看终态看不到的部分。
- **窗口外的残留同样被直接看到**：9 个「回填晚于第二删」的轮次里 100% 采样为 V0，观测下界 2.7–4.1s（采样窗口长度），恢复点记为「未观察到」而不是"已恢复"。
- **503 是真实协议现象**：每次 `pause=1500/2000` 都有 1 个采样读返回 `{"code":503}`（服务端在等待键锁后失败），一次 `pause` 轮内最多 1 个；这些样本记为 `failures`，不计入陈旧比例，也未丢弃或重试拉绿。
- **采样分辨率有限且如实记录**：采样读会阻塞在同一把键锁上（中位 7–9ms；被慢读者挡住时可达 0.5–1.0s），所以每轮只有 10–125 个采样点，不能当作毫秒级恢复曲线；首个采样点距 commit 15–32ms。

### 12.1 缺陷：阻塞等待期间不推进已完成请求的留存

上一版把「已发出的同步 HTTP 等它返回」写成一次阻塞调用（`SendAsync(...).GetAwaiter().GetResult()`）。慢读的完成观察与落盘只发生在**这次调用返回之后**，于是：

- 客户端 Task 已经完整收完慢读响应，但另一个 sample 还在阻塞，慢读那条记录一直不在盘上（负责人独立实证阻塞段 ≥1445ms 缺记录）；
- 中途退出就会丢掉这条**已经完成**的慢读；
- 自报的 8ms 只是「发现完成→写标」的延迟，不是真实完成→Flush。

### 12.2 修法（只改工具，三个文件）

1. **`Update-P13c4Tracked`**：遍历所有在途请求。Task 已完成 → 立刻建记录并 Flush；未完成 → 只刷新 `last_incomplete_ms`（**最后一次看见它仍未完成**的时刻）。
2. **`Send-P13c4Responsive`**：本卡**唯一**的 HTTP 等待方式，把等待切成 3ms 片，每片先 `Update-P13c4Tracked`，所以「同步」调用方阻塞期间留存照常推进。窗口脚本的 `Send-Once`、`Wait-Event` 采样循环全部改走它。
3. **时间戳分四段，不再用同一个 now 自证**：`dispatched_ms`（发出前）→ `last_incomplete_ms`（最后一次见未完成）→ `task_completed_observed_ms` / `ended_ms`（首次见到客户端 Task 完成）→ `persisted_ms`（行内写标，序列化前）；`flush_returned_ms`（`Flush(true)` 返回）**不能写进它刚变持久的那一行**，按卡要求**另列**在运行结果的 `reader`/`blocked_sample` 里。真实完成时刻被 `(last_incomplete_ms, ended_ms]` **夹逼**，不再宣称某个轮询戳就是完成时刻。
