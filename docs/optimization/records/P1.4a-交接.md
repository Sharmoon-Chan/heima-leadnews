## 4. 采集器必须做到的事（都已实现并被离线证明）

1. **定速与上限**：slot i 在 `planned_offset_ms=round(i*1000/rate)` 到期；在途上限 16（离线可用小值），到期时若在途已满该 slot **记 dropped 且不再排队、不重试**；单请求超时 5 秒（离线用 500ms 证明会真触发）。对账 `offered = started + dropped`、排空后 `started = completed`。
2. **完整原件**：每条响存 `http/headers/bytes/sha256/body_utf8/body_base64`，**正文含换行/逗号/引号/制表符/中文都不失真**；传输失败时只写 `body_unavailable`，**不补造 body/bytes**。
3. **持续落盘**：每条记录 `WriteLine + Flush()`（其他进程立即可读），`FlushFileBuffers` 每 ≤50 条或 ≤200ms 一次并计数；`Close()` 再刷尾。**明确不宣称逐条 fsync**；进程被杀不会丢已 Flush 的行，OS 崩溃最多丢最后一个未 fsync 段。
4. **服务端归属**：按 `X-P1-Request-Id` 把每条响应接到探针事件 → `cache.read hit=true/false`、`rebuild.begin writeCache=`、`db.enter`（DAO 调用）；本卡**只用 DAO 证据**，物理 SQL 未采集，**不换名为 SQL**。
5. **资源**：按 1 秒记录「目标实例 PID / 采集进程 / 空闲组实例」的 CPU 累计与归一化百分比、工作集、线程数；JVM 堆/GC 用 `jstat -gc 1000` 全程留档；连接池指标无 Actuator/harness，标为 unavailable。
6. **从原件汇总**：`p14a-summarize.ps1` 重读每份 ledger 与事件文件重算分位数（nearest-rank，`ceil(p/100*n)`）、命中/回源/DAO 与对账；`problems=0` 才接受。
