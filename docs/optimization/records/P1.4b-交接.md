## 2. 测量路径合同（已实现）

### 资源不再阻断派发

- CPU/内存/线程由**独立进程** `p14b-observer.ps1` 采样：自己的 PID、自己的 `resources.csv`、自己的 write-once `observer-summary.json`（区间、缺口、每次采样成本、找不到的 PID）。
- 采集器只负责：启动它 → 等它的就绪标记（**首个采样完成之后**才写就绪，避免进程启动/JIT 落进测量窗口）→ 跑完 → 写停止标记 → 等它退出 → 读它的摘要。
- 采集器代码里**已经没有任何资源采样/写盘路径**；主 dispatch/reap 循环不会等采样也不会等资源写盘。
- PID 归属：观察者摘要里的 `observer_pid/collector_pid/target_pid` 必须与 collect-result 一致（`pid_identity_matches`），否则该 run 失败；`TargetPid` 来自实例 manifest，`IdlePid` 是另一组实例，绝不「取最近的 java」。

### 四条时间戳，同一单调轴

| 字段 | 取点 | 说明 |
