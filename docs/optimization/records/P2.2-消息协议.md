# P2.2：文章索引事件与成功标记协议

日期：2026-11-08。P2.1经未参与实现的子agent独立验收通过后，用户授权继续本卡。版本保持Spring Kafka2.6.6、Kafka clients2.5.1及现有Redis/ES依赖。

## 1. 新消息

文章静态化完成后的一次逻辑索引调用产生一个schemaVersion=1的消息：

| 字段 | 语义 |
|---|---|
| schemaVersion | 整数1；未知版本具名拒绝并走现有DLT |
| eventId | UUID字符串；一次逻辑索引调用只生成一次 |
| articleId | 精确正Long的十进制字符串，不经double |
| occurredAt | 事件创建时间，epoch毫秒；不是文章单调版本 |
| payload | 原SearchArticleVo，包含文章id、标题、正文、静态地址等 |

Kafka key为articleId，header eventId与消息内eventId一致。生产端组装后序列化一次，将同一个ProducerRecord交给KafkaTemplate；Kafka客户端重试以及DLT/人工重放复用原内容和事件ID。同文章下一次save/index调用生成新ID。没有Outbox或上游请求去重：客户端重新调用save形成的新执行不保证沿用之前的eventId。

消费者校验版本、事件ID格式、articleId字符串范围、正整数occurredAt、payload.id精确匹配；header若存在，每个值都必须与消息内ID相同。ES只写payload，不将消息封装写入业务索引。消息格式升级采用“消费者先上线兼容新旧格式，再更新生产者”的顺序。

原始SearchArticleVo消息继续可消费，但**跳过Redis业务事件去重**；旧header或源topic/partition/offset不冒充稳定业务事件ID。原P2.1错误分类、有限重试及确认式DLT保持。

## 2. Redis成功标记

参数：

- `leadnews.search.dedup.enabled=true`，可关闭进行对照；
- `namespace=leadnews:search:processed:`，key拼接目标ES索引及eventId；
- `ttl-seconds=86400`，即24小时的有界识别窗口，属于本次选定起点而非生产最优证明；
- 当前本地测试环境使用Redis DB5，命令超时500ms。连接建立可能有额外开销。

标记值为 `v1:<articleId>:<canonical-payload-SHA256>`。payload对象字段递归排序后求hash；已知eventId携带不同内容时视为协议冲突进入DLT，不把它静默当作相同事件。

处理顺序严格为：**查询成功标记 → 未命中则写ES → ES返回成功后写带TTL的标记**。没有预先SETNX“成功”，也不通过分布式锁声称只执行一次。Redis TTL写入是单个带过期命令，生产代码使用现有StringRedisTemplate。

| 情况 | 行为 |
|---|---|
| 标记命中且绑定内容相同 | 跳过ES，记录dedup-hit |
| 标记缺失 | 正常写ES，成功后记标记 |
| Redis查询失败 | 记录redis-read-failed，继续ES路径，允许去重收益下降 |
| ES失败 | 保持P2.1重试/DLT，不写成功标记 |
| ES成功但Redis写标记失败 | 记录redis-write-failed，保留ES成功，不将它误报成索引失败；再投可能再次写ES |
| 同文章新eventId | 独立事件，正常写入，不被旧标记阻止 |
| 标记TTL到期 | 重新处理允许发生 |
| 并发相同事件 | 查询与写入非原子，两个线程都可能未命中并各写一次 |

相同文章key只提供同分区内顺序基础，不覆盖跨topic/人工重放的全局顺序。本卡没有单调contentVersion保护：未见过的旧事件在新事件后到达，仍可能覆盖新内容。UUID只用于身份，不用于比较新旧。

## 3. 人工重放

`benchmarks/kafka/P22ReplayCli.java`复用P2.1的有界单条机制，范围限定本卡p22测试topic。精确DLT坐标、eventId、原目标、预览payload SHA一致且显式执行才发送；原key/value/headers保持，重放另有身份和journal。第一次成功重放写ES并留成功标记；第二次同事件重放应跳过ES，DLT原记录仍保留作证据。

没有header的旧消息仍可正常消费，但当前人工工具拒绝缺少显式eventId的记录，避免自动猜测业务身份。对普通课程topic的批量重放不在本卡授权范围。

## 4. 适用边界

ES与Redis之间无原子事务。进程在ES成功后、标记写入前崩溃，源消息重投会再次索引；单ID覆盖仅保证目标文档身份，不证明副作用只发生一次。Redis标记丢失、TTL到期和并发竞态也允许重复写。详见[有限验证报告](P2.2-MQ-DUP报告.md)，不宣称Exactly Once、零丢失、乱序安全或生产容量。
