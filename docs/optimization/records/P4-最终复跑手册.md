## 参数及依据

| 参数 | 当前值 | 依据/限制 |
|---|---|---|
| 详情有效/空值缓存 | 1800s+jitter最高300s / 60s | 已有功能值，非生产最优 |
| 热点锁 | 租期3000ms，等待1000ms，backoff10–50ms | 原受控锁/预算验证，租期过期边界保留 |
| 第二删 | 默认500ms、最大活跃256、关闭等待2000ms | 原候选实验保持，非强一致或持久任务 |
| Kafka producer | acks=all、幂等true、retries10、inflight5，max.block5s/request5s/delivery15s | 单副本不保证高可用 |
| 消费失败 | 首次后3次重试、间隔1000ms，DLT Future等待20s | 总预算还含send的max.block；失败会阻塞同分区 |
| 事件标记 | DB5，namespace含索引/eventId，TTL86400s，timeout500ms | ES成功后标记，GET/ES/SET非原子 |
| 并发 | 正常1，多分区受控实验候选2 | 原正常topic1分区，不直接推广实验并发 |
| 分页 | 默认10/最大50，time DESC+id DESC，固定首屏上界 | 20只是性能实验值；ES7.4无本卡PIT |

## 回退和保留

旧/search入口仍在；回退它会恢复同时间漏项，不能称无代价。消息升级顺序消费者先兼容、生产者后发新封装；不能回退消费者为raw-only却继续发新事件。Redis去重可关闭，P2.2已测同代码开关对照；这不是丢弃事件的开关。

源码快照、脏diff、配置原文和恢复备份在各artifact根inputs。恢复前先核对依赖实例，不能重置无关代码、管理员账号或清历史topic。最终精确清理见P4/evidence/cleanup.json；所有失败样本保留，正式简历PDF不改。
