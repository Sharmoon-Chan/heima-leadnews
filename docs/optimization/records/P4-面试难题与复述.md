# 面试难题与复述练习

真实来源为本地补充优化和受控实验，不称线上事故。每条建议练60–90秒，用自己的语言解释。当前用户尚未在本聊天亲自复述或复跑，掌握状态未验证。

## 1. 两次删缓存为什么仍会读旧值

我把写库和删缓存放进真实事务时序看：事务未提交就删缓存，另一个请求可能读到旧库值并回填。改为事务成功提交后失效，保留有界延迟第二删；用精确ID的提交前暂停，观察事务中回填和提交后可见性。最终三轮均提交前旧、提交后新，热点12并发每轮只1次回源。它仍非强一致：慢回填能越过500ms窗口，进程崩溃会丢内存任务，因此不能把双删当分布式事务。

追问：update调用返回不等于commit；锁令牌比较删除避免旧持有者删掉新锁，但租期过期仍需单独讨论；500ms来自已有受控选择，不是任何场景陈旧上限或生产最优。

## 2. 死信发送失败为什么不能算恢复

项目实际Spring Kafka2.6.6原死信发布只记录send失败，方法返回不等于broker收到。我保留原库生成payload/异常headers，只在publish边界等待确认并传播失败。真实测试broker不可达、DLT缺分区、ISR不足和delivery超时，源offset没有越过未恢复消息；修复后后续继续。人工重放要求精确坐标、eventId、payloadSHA，先记意图、确认后记offset。代价是同分区阻塞；超时可能晚确认，ES成功提交前崩溃仍会重复，不是Exactly Once。

追问：单副本acks=all没有额外冗余，数据库与MQ也不原子；Redis只在ES成功后记标记，读失败继续ES、标记写失败保留ES成功；同文章新修改用新eventId，不能用articleId作永久去重键。

## 3. 时间游标为什么也漏数据

原项目不是大offset，它按publishTime小于上一页最后时间再from0取一页。35条同时间记录跨页时，严格小于把余下记录全部排除，123真值只返97。新增time DESC+唯一long ID DESC完整排序元组，cursor固定首屏上界、查询指纹和最后实际返回sort值，外部ID字符串保真。冻结数据多页大小完整；10万数据另与明确标识的实验offset比较。ES7.4下本卡无PIT，更新/删除/补插旧时间仍能改变集合，动态反例已记录。

追问：用业务long的doc_values，不用_id排序；size+1的cursor取最后返回项而非探测项；随机第400页必须已备cursor，单页测量排除的准备成本在累计400请求中另报。
