## P1.1a 首轮实施记录（2026-10-29，待下述补修）

落在单一公共脚本 `benchmarks/lib/RunDirGuard.ps1`，五个入口（`p1-1-cache-func.ps1`、`p1-1-backfill.ps1`、`p1-detail-evid001.ps1`、`p0-detail-load.ps1`、`p1-prewarm.ps1`）在第一条 HTTP/Redis/SQL 之前调用：

1. `Start-RunDirectory`：run_id 合法性 → OutDir 末级必须等于 run_id → 必须位于实验根内 → 目标目录已存在（含空目录）即抛错，不 Force/不删除/不换后缀 → 建目录后立即写 `run-manifest.json`（含脚本 SHA256、脱敏参数、targets、data_set）。
2. `Write-RunFileText/Bytes`：同一路径第二次写入直接抛错，**任何响应/步骤文件只创建一次**。
3. `Add-RunCheck` + `Get-RunCheckCounts`：pass / fail / skipped 三计数独立；`Set-RunStatus` 只在 `failed == 0` **且** `passed > 0` 时返回 0，因此「只有 skipped」的运行判 failed。
4. `Save-RunFailure`：写 `run-error.json`（错误、栈、已完成步骤、计数）与 `run-error-output.txt`，**不清除任何已写文件**，返回退出码 1。
5. `Test-DetailResponse`：HTTP 200 + 业务码 + `data.article.id` 精确字符串一起判定；HTTP 200 单独不算成功。

退出码约定：0 通过，1 检查失败或运行中异常（文件保留），2 用法/目录保护问题（未执行任何外部调用）。
