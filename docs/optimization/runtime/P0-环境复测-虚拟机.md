两个新发现的运行时陷阱（都已在问题台账登记）：

**(a) ENV-004：本次 Windows/JVM/Nacos 组合下中文配置解析报错，配置未生效**

```
ERROR NacosPropertySourceBuilder : parse data from Nacos error, dataId:leadnews-article-dev.yml
org.yaml.snakeyaml.error.YAMLException: java.nio.charset.MalformedInputException: Input length = 1
```

- Nacos 上的配置本身是**合法 UTF-8**（对原始字节做严格校验通过，响应头 `charset=UTF-8`）；
- 根因是 spring-cloud-alibaba 2.2.5 解析时用 JVM 默认字符集，本机默认 GBK，把中文注释读坏；
- 后续错误容易误导：配置不生效，连 `driver-class-name` 都丢了，于是 Boot 2.3 推断出
  `com.mysql.cj.jdbc.Driver`（项目只有 5.1.46 的 `com.mysql.jdbc.Driver`），报
  `Failed to load driver class com.mysql.cj.jdbc.Driver`。本轮先解决前置配置解析，避免误将级联报错当作唯一根因；驱动升级应另行评估；
- 解决：启动加 `-Dfile.encoding=UTF-8`。

**(b) 本次 bootstrap/Nacos 配置下命令行覆盖未按预期生效**

本轮记录显示，在当前 Spring Cloud bootstrap 配置下，Nacos 属性值未被这些命令行参数覆盖，因此
`--spring.datasource.url=...`、`--spring.redis.host=...` 这些覆盖**不生效**（实测：仍然用 Nacos 的
`root` 账号连接，报 `Access denied for user 'root'@'localhost'`）。`-Dspring.cloud.config.override-none=true`
在本版本也不起作用。

本轮采用的干净做法：**在 Nacos 上新增一个 profile 配置** `leadnews-article-p0.yml`，
内容从 `-dev` 派生，只改「本机实际依赖地址」（MySQL/Redis 指到 127.0.0.1、Redis 无密码、
使用 native 认证的专用账号），然后用 `--spring.profiles.active=p0` 启动。
**原有 15 个配置一个都没改**，可以随时删掉这个 dataId 回滚。

**(c) ENV-005：MySQL 8.0 默认认证插件与 mysql-connector-java 5.1.46 不兼容**

`mysql.user` 里 `root@localhost` 的 plugin 是 `caching_sha2_password`，5.1.46 驱动不支持。
本轮没有改 root，而是新建专用账号：

```sql
CREATE USER 'leadnews'@'localhost' IDENTIFIED WITH mysql_native_password BY '<从本地私有配置读取的口令>';
GRANT ALL PRIVILEGES ON `leadnews_article`.* TO 'leadnews'@'localhost';  -- 其余 3 个库同
```

（可回滚：`DROP USER 'leadnews'@'localhost';`）

### 3.4 leadnews-search：**启动失败（MQ-001 已复现）**

```
BeanCreationException: Error creating bean with name 'syncArticleListener'
Caused by: org.springframework.beans.BeanNotOfRequiredTypeException:
  Bean named 'kafkaErrorHandler' is expected to be of type
  'org.springframework.kafka.listener.KafkaListenerErrorHandler'
  but was actually of type
  'org.springframework.kafka.listener.SeekToCurrentErrorHandler'
```

对应源码：`SyncArticleListener` 第 25 行
`@KafkaListener(topics = ..., errorHandler = "kafkaErrorHandler")`，而
`KafkaErrorHandlerConfig` 里的 `kafkaErrorHandler` Bean 是 `SeekToCurrentErrorHandler`。
注解的 `errorHandler` 属性要求 `KafkaListenerErrorHandler` 类型，两者不匹配。

**问题状态从「静态风险」升级为「实验复现的真实启动故障」**。按 P0 边界**只记录、不修**，留到 P2.0。
原始栈：`_optimization-artifacts/20261029-P0-VM/search-failure.snapshot.log`。

MongoDB(27017)、ES(9200)、Kafka(9092) 三个依赖在此时可连，原栈明确给出了代码接线类型错误；该错误是确定阻塞。修复后是否暴露其他问题仍需实际启动验证，不能以端口可连排除所有外部问题。
