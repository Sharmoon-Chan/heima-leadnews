## 3. 网关外部路径：**已核实（2026-10-29 复测）**

> 本节原写于 2026-10-28，当时 Nacos 不可达，结论是「未核实」。2026-10-29 虚拟机网络修复后已实测，
> 证据见 [P0-环境复测-虚拟机.md](P0-环境复测-虚拟机.md) 与 `_optimization-artifacts/20261029-P0-VM/`。

- 三个网关的 `bootstrap.yml` 内确实**没有** `spring.cloud.gateway.routes`，路由**全部来自 Nacos**
  配置 `leadnews-app-gateway`（已导出，见 `_optimization-artifacts/20261029-P0-VM/nacos/leadnews-app-gateway.yaml`）。
- 实测路由定义：

  ```yaml
  - id: article   uri: lb://leadnews-article   predicates: [Path=/article/**]   filters: [StripPrefix=1]
  - id: user      uri: lb://leadnews-user      predicates: [Path=/user/**]      filters: [StripPrefix=1]
  - id: leadnews-search  /  leadnews-behavior  /  leadnews-comment   （同构）
  ```

- **外部真实路径 = `GET http://<网关>:51601/article/api/v1/article/detail/{id}`**，
  `StripPrefix=1` 去掉 `/article` 后落到服务的 `/api/v1/article/detail/{id}`。
- 实测结果（gateway 与 article 同时启动，`token` 头由仓库现成 `AppJwtUtil.main` 生成）：

  | 请求 | 结果 |
  |---|---|
  | 不带 `token` | **401**（AuthorizeFilter 生效） |
  | 带合法 `token` | **200** + 业务码 200 + 真实文章 JSON（路由与 StripPrefix 生效） |
  | 带 token 且 ID 不存在 | 200 + 业务码 **1002** |

## 6. 缓存命中与响应不一致的证据

以 MySQL general log 为准（`_optimization-artifacts/20261028-P0-RUN/cache-hit/general.log`）：
连续两次请求同一 ID，日志中只出现 2 条 SELECT，且都发生在第一次请求：

```sql
SELECT id,title,...,static_url FROM ap_article WHERE id=1000005
SELECT id,article_id,content FROM ap_article_content ...
```

即第二次请求没有产生任何 DB 查询 —— 缓存命中成立。

同时发现一个**当前未提交改动的行为差异**（本轮不修，按 P0 边界只记录）：
第一次（回源）响应里 `data.article.id` 是**字符串** `"1000004"`，第二次（读缓存）响应里是**数字** `1000004`，
且 `images` 字段在某一侧为 `null` 而另一侧不出现。原因是缓存侧走 `fastjson` 反序列化成 Map 后由 Jackson 输出，
与 POJO 序列化的类型/字段策略不同。真实文章 ID 已大于 2^53-1，数字输出还可能造成部分客户端精度损失，不能仅当作显示差异。
见问题台账 `CACHE-006`，负责人已将其前移到 P1.0 的共同契约修复。
