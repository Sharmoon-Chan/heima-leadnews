### 4.1 S：真实异步工作线程的 static_url 写入

S 的入口是 `P13bHarnessController /p13b/harness/staticize`，它调用**真实** `ArticleFreemarkerService.buildArticleToMinIO`（`@Async`），本轮的替身只有出网点：

- `FileStorageService`（`@Primary`，仅本轮装配）：返回 `p13b-rebuilt://html/<id>.html`，并记录上传的 HTML **是否含模板渲染出的 `P13b-marker`**；
- `KafkaTemplate`（`@Primary`）：记录调用，不发送；对 `p13b.rollback.kafka.article-id` 指定的文章**同步抛异常**。

Freemarker 模板、异步线程、DAO、事务、失效器都是真的。工作线程事件原件（PRE 与 POST 同一行格式）：

```
epochMs=1793428447690 pid=49732 thread=task-2 runId=- requestId=- event=static_url.updated
  reqId=0 articleId=9007199254741015 path=p13b-rebuilt://html/9007199254741015.html inAsyncWorker=true txActive=true
```

`thread=task-2` 说明这段代码确实跑在 Spring 的异步线程池里；`runId=-` 是因为 `@Async` 线程没有请求上下文，所以脚本按 `articleId + 时间窗` 选事件，不按 `runId`。调用方返回耗时 8.1 ms / 8.5 ms，返回体明确写 `"note":"return = task submitted, NOT written"`；DB 的 `static_url` 与上传记录在之后才出现（脚本轮询 `html_uploads` 与 DB 列）。

`P13b-marker` 是正文数组 `[{"type":"text","value":"P13b-marker"}]` 经真实模板渲染后由替身看到的，因此「模板真的跑了」有原件支持，不是只看 URL。

### 4.2 S 回滚：真实异步事务内的回滚

`P13b-POST-SROLLBACK-r02`：worker 事务内 `UPDATE static_url` 已执行、`cache.evict.register` 已登记，随后 `KafkaTemplate` 替身在**同一线程**同步抛 `RuntimeException` → 该 worker 事务回滚。脚本等到 `register` 事件出现（说明 UPDATE 与登记都发生过）后才读 DB，并额外等 800 ms：

| 断言 | 原件 |
|---|---|
| DB `static_url` 未变 | 前后均为 `p13b-rebuilt://html/9007199254741016.html` |
| 缓存未被删 | `article:detail:9007199254741016` `EXISTS=1` |
| 没有成功提交回调 | `afterCommit(static_url)=0` |
| 没有删除动作 | `cache.evict.ok`（static_url） = 0 |

口径：该文章在本阶段早先的 S 运行里已有非空 `static_url`，所以这里证明的是「回滚后与回滚前一致 + 登记发生但提交回调与删除都没发生」，不是「NULL 保持不变」。调用方线程的事务无法替异步线程回滚，本场景的回滚发生在 worker 自己的事务内。

### 4.3 B：public updateScore 的行为计数写入

B 走真实 `ApArticleServiceImpl.updateScore(ArticleVisitStreamMess)`（harness 只负责构造消息并调用公开方法），DB 由 `mysql -e` 独立查询核对，缓存由 `redis-cli EXISTS` 独立核对：

| 变体 | 计数 views / likes / comment / collection | 提交后缓存 | 事件 |
|---|---|---|---|
| PRE | 74093/2302/236/391 → 74100/2305/238/392 | `EXISTS=1`（旧值仍在） | `register=0 afterCommit=0` |
| POST | 74100/2305/238/392 → 74107/2308/240/393 | `EXISTS=0`，随后详情 `views=74107` | `register=1 afterCommit=1` |

`behavior_count.updated` 事件里带四个字段的实际值，可与 DB 逐字段对账。BROLLBACK 用 `--p13b.rollback.updateScore.<id>` 夹具：登记后抛异常 → DB 计数不变、缓存未被删、`afterCommit(updateScore)=0`、`p13b.controlled_rollback=1`。**不把「调用返回 ok=false」当回滚证据**，DB 与缓存是独立核对项。

### 4.4 N：dto.id=null 的真实新增

- 请求 DTO 的 `id` 为 `null`（返回体 `"dtoIdWasNull":true`），走 `saveArticle` 的 `isCreate` 新增分支；
- 先做详情读到 1002，并确认 `article:detail:9007199254741019` 存在（空值占位）；
- ID 由实验装配的 `IdentifierGenerator` 产出：`MybatisPlusPropertiesCustomizer` 里挂只影响 `ApArticle` 的生成器，仅当配置的 `article.p13b.id-fixture.article-id` 命中时返回 `9007199254741019`，其他实体与普通请求委托原生成器。**生产 ID 算法未改**；
- 三表精确行数：`ap_article 0→1`、`ap_article_content 0→1`、`ap_article_config 0→1`（断言按 `before+1` 写，避免把种子既有行数当成本次插入）；
- 提交后 `afterCommit(saveArticle:create)=1`，空值占位被删（`EXISTS=0`），再读为 200、`title=P13b-created`、`"id":"9007199254741019"`（JSON 字符串）。

### 4.5 最小回归

`P13b-POST-REG-r03` 覆盖 `saveArticle` 的更新分支：提交 → 缓存失效 → 新标题；冷读与热读响应 **495 字节逐字节相同**；大 ID 精确字符串；不存在 ID 返回 1002；同分支受控回滚 → 标题不变、`afterCommit(saveArticle:update)=0`、无 `saveArticle:update:afterCommit` 删除事件。

回归过程中发现并修正了脚本的一处错误断言：原先断言「回滚后缓存未被删」，但同一次 `saveArticle` 调用还会触发**异步 static_url worker**，那个 worker 有自己的事务并且合法提交、合法删除缓存。该断言改为只针对 `saveArticle` 事务自身的事件（`afterCommit(saveArticle:update)=0` 且无该相位删除）。这不是业务缺陷，是脚本把两件事混在一起。

## 6. 口径与限制

1. **替身边界**：只替换 `FileStorageService`（返回标注 URL、记录 HTML 是否含标记）与 `KafkaTemplate`（记录、不发送、对指定文章抛异常）。真实 MinIO 上传、真实消息发送、ES 落地仍归 P2.0；本轮不宣称静态化端到端可用。
2. **N 的 ID 夹具**：只对配置精确匹配的 `ApArticle` 生效，配置项 `article.p13b.id-fixture.article-id` 在启动参数里显式给出；生产 `IdentifierGenerator` 未改。新增分支的 ID 来自夹具，不是生产算法产出的随机 ID。
3. **热榜 key**：真实 `updateScore` 会写 `hot_article_first_page_<channel>` / `hot_article_first_page___all__`。本轮没有做「替换热榜协作者」或「隔离 Redis DB」的装配，这是与任务卡建议的偏差；运行结束时 `KEYS 'hot*'` 返回空，本地 Redis 中不存在这些 key，课程库与课程热榜数据未被保留性修改。**下一卡若继续跑 updateScore，应先做热榜协作者替身或隔离 DB**。
4. **DB/缓存判定**：全部用独立客户端读取（`mysql -e`、`redis-cli EXISTS/KEYS`），不以脚本自己写的 DEL 日志当结论。
5. **P1.3a 既有风险不变**：500 ms 以外的旧读回填、多进程竞态、延迟任务生命周期与参数选择仍在 P1.3c，本轮不重做也不宣称覆盖。
6. 单机、隔离库、单轮小样本；所有「秒」「条/百次读」都是本轮实测值，不是稳态容量。
